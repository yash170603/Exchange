## F2 · `String()` methods `[ ]`

**File:** `orderbook/order.go`
**Signatures:**
```go
func (t OrderType) String() string
func (s OrderStatus) String() string
```
**Does:** returns `"BUY"` / `"SELL"`, and `"OPEN"`, `"PARTIALLY_FILLED"`, `"FILLED"`, `"CANCELLED"`,
`"REJECTED"`. For any other number, return something like `OrderType(7)` so bugs are visible.

**Go to use:** `switch`, `fmt.Sprintf`, **value receivers** (small type, read-only, so no `*`).

**System idea:** Go interfaces are satisfied *implicitly*. `fmt` has an interface `Stringer`
(`String() string`). Once you add this method, `fmt.Println(Buy)` prints `BUY` instead of `0`,
with no "implements" keyword anywhere. Your logs and test failures become readable for free.

**Tests:** `fmt.Sprint(Buy) == "BUY"`, `fmt.Sprint(OrderFilled) == "FILLED"`, `fmt.Sprint(OrderType(9))`
shows the number.

**Watch out:** don't call `fmt.Sprint(t)` *inside* `String()`. It calls `String()` again, forever.
Convert to `int` first.

## F3 · Sentinel errors `[ ]`

**File:** `orderbook/errors.go` (new)
**What:** package-level error variables, made once with `errors.New`:

| Name | When |
|---|---|
| `ErrInvalidQty` | qty ≤ 0 |
| `ErrInvalidPrice` | price ≤ 0 on a limit order |
| `ErrWrongEntity` | order's `Entity` isn't this book's |
| `ErrUnknownOrderType` | `OrderType` isn't `Buy` or `Sell` |
| `ErrOrderNotFound` | cancel of an id that isn't resting in the book |

**Go to use:** a `var ( ... )` block, `errors.New`. Callers check with `errors.Is(err, ErrInvalidQty)`.
To add detail, wrap: `fmt.Errorf("%w: got %d", ErrInvalidQty, qty)`. `errors.Is` still matches.

**System idea:** callers (the gateway in M4) need to know *which* rejection happened, to send the
trader a reason code. A sentinel error lets code check *what* went wrong; the wrapped text tells
*humans* the details.

**Go style:** error strings start lowercase, have no full stop, and are prefixed with the package:
`"orderbook: qty must be positive"`. Your current `"Error occured in orderValidation"` breaks all three.

## F5 · `validate` `[ ]`

**File:** `orderbook/book.go`
**Signature:** `func (b *OrderBook) validate(o *Order) error` (lowercase: only the book calls it)
**Does:** checks, in this order, returning the first failure:
1. `o.OrderType` is `Buy` or `Sell` → else `ErrUnknownOrderType`
2. `o.Qty > 0` → else `ErrInvalidQty`
3. `o.Price > 0` → else `ErrInvalidPrice` (F11 relaxes this for market orders)
4. `o.Entity == b.Entity` → else `ErrWrongEntity`
5. returns `nil`

**Go to use:** guard clauses (check, return early, no `else`), `fmt.Errorf` with `%w`.

**Tests:** one table row per failure; check with `errors.Is`, not by comparing strings.

**Watch out:** this replaces `isOrderRquestValid`. Don't print anything, just return errors.

## F6 · `rest`: insert keeping best-first `[ ]`

**File:** `orderbook/book.go`
**Signature:** `func (b *OrderBook) rest(o *Order)`
**Does:** puts `o` into `b.buys` or `b.sells` at the right position, so index 0 is always the best.

| Side | Goes before an existing order `x` when |
|---|---|
| buys | `o.Price > x.Price`, or same price and `o.Seq < x.Seq` |
| sells | `o.Price < x.Price`, or same price and `o.Seq < x.Seq` |

Steps:
1. Find the first index `i` in the side where `o` should go before `side[i]`. If none, `i = len(side)`.
2. Insert `o` at `i`.

**Go to use:** `slices.IndexFunc` (with a closure), `slices.Insert`. Suggested helper so the logic
isn't written twice:
```go
func insertSorted(side []*Order, o *Order, before func(a, b *Order) bool) []*Order
```
Functions are values in Go: pass a different `before` for buys and for sells.

**System idea:** *keep sorted on write* vs *sort on every read*. Matching reads the best order
constantly, so pay the cost once at insert. The cost: `slices.Insert` shifts every later element,
O(n). That's fine for now; M10 replaces it with something faster, with numbers.

**Tests:** Buy @98 then Buy @100 → buys `[100, 98]`. Sell @102 then Sell @99 → sells `[99, 102]`.
Buy A @100 then Buy B @100 → `[A, B]`.

**Watch out:** `slices.Insert` returns a new slice header. You must assign it back
(`b.buys = ...`), or the insert is lost. Same reason as the value-receiver bug.

## F7 · `BestBid` / `BestAsk` `[ ]`

**File:** `orderbook/book.go`
**Signatures:**
```go
func (b *OrderBook) BestBid() (price int64, ok bool)
func (b *OrderBook) BestAsk() (price int64, ok bool)
```
**Does:** returns the best buy / sell price. If that side is empty: `0, false`.

**Go to use:** the **comma-ok idiom**, the same pattern as `v, ok := m[key]`. It's why the
function doesn't return `0` alone: `0` might look like a real price.

**System idea:** "bid" = best price someone will buy at, "ask" = best price someone will sell at.
A healthy book always has bid < ask. If bid ≥ ask, something should have matched: that's a bug.
F14 tests exactly this.

**Tests:** empty book → `ok == false`. After resting orders → correct prices.

## F8 · `Submit`, no matching yet `[~]`

**File:** `orderbook/book.go`
**Signature:** `func (b *OrderBook) Submit(o *Order) ([]Trade, error)` (rename from `InsertOrder`)
**Does:**
1. `validate(o)`. On error: set `o.Status = OrderRejected`, return `nil, err` (keep the original
   error, don't replace it with a new one).
2. Move the counter forward and stamp `o.Seq`. First order gets `1`. Rejected orders don't use a seq.
3. Set `o.OrigQty = o.Qty`, `o.Status = OrderOpen`.
4. `rest(o)`.
5. Return `nil, nil`. A nil slice means "no trades".

**Review notes on your current `InsertOrder`:**
1. Line 23 throws away the real error and returns a vague one. Return `err` itself.
2. Line 27 bumps `nextTradeID`. Trade IDs are only for trades (F9), so remove it.
3. Lines 26–31 handle seq twice. You only need: move the counter, copy it to the order.
4. The `default` case prints. Unknown types are now caught by `validate`, so it can go.
5. Receiver: rename `orderBook` → `b`.

**System idea:** the book keeps the caller's `*Order`. If the caller changes that order after
submitting, the book's data changes under its feet. Remember this. M2 fixes it by passing copies
through channels.

**Tests:** three valid orders get seq 1, 2, 3. An invalid order returns the error, has status
`REJECTED`, isn't in the book, and doesn't use up a seq.

## F9 · `match`: full, partial, sweep `[ ]`

**File:** `orderbook/book.go`
**Signature:** `func (b *OrderBook) match(o *Order) []Trade`
**Does:** matches the incoming order `o` against the opposite side, best first:
1. Opposite side: `b.sells` if `o` is a buy, `b.buys` if it's a sell.
2. Loop while `o.Qty > 0` and the opposite side isn't empty:
   1. `best` = opposite side's index 0.
   2. **Does the price cross?** Buy: `best.Price <= o.Price`. Sell: `best.Price >= o.Price`.
      If not, stop. Nothing further down will cross either.
   3. `qty = min(o.Qty, best.Qty)` (Go has a built-in `min`).
   4. Make a `Trade`: next trade ID, `Entity`, buy/sell order IDs (depending on who's who),
      **`Price = best.Price`** (the resting order's price), `Qty = qty`, `Status = TradeExecuted`.
   5. Subtract `qty` from both `o.Qty` and `best.Qty`.
   6. `best.Qty == 0` → `best.Status = OrderFilled`, remove it from the front of the side.
      Otherwise `best.Status = OrderPartiallyFilled`.
3. After the loop, set `o.Status`: `Qty == 0` → `FILLED`, `Qty < OrigQty` → `PARTIALLY_FILLED`,
   otherwise stays `OPEN`.

`Submit` becomes: validate → stamp → `trades := b.match(o)` → if `o.Qty > 0`, `rest(o)` → return `trades, nil`.

**Go to use:** `for` with a condition, built-in `min`, `slices.Delete` or re-slicing.

**System idea: hidden memory leak.** Removing the front with `side = side[1:]` hides the old
element but the array still points to it, so the filled `*Order` can't be garbage-collected
until the array is replaced. `slices.Delete` clears the leftover slot. Know why you pick one.

**Tests (one row each):**
| Case | Book | Incoming | Trades | Left in book |
|---|---|---|---|---|
| no cross | sell 5@101 | buy 5@100 | none | sell 5@101, buy 5@100 |
| exact fill | sell 5@100 | buy 5@100 | 5@100 | empty |
| incoming bigger | sell 4@99 | buy 10@100 | 4@99 | buy 6@100 |
| resting bigger | sell 10@99 | buy 4@100 | 4@99 | sell 6@99 (`PARTIALLY_FILLED`) |
| sweep | sell 4@99, 3@100, 5@102 | buy 10@100 | 4@99, 3@100 | sell 5@102, buy 3@100 |
| time priority | sell A 2@100, then B 2@100 | buy 2@100 | with A | sell B 2@100 |
| resting price wins | buy 5@100 | sell 5@98 | 5@**100** | empty |

## F10 · `Cancel` `[ ]`

**File:** `orderbook/book.go`
**Signature:** `func (b *OrderBook) Cancel(id int64) error`
**Also:** add `byID map[int64]*Order` to `OrderBook`; make it in `NewOrderBook`; add to it in
`rest`; delete from it in `match` when a resting order is filled.
**Does:**
1. Look up `id` in `byID` (comma-ok). Not there → `ErrOrderNotFound`.
2. Find it in its side (`slices.IndexFunc`, comparing pointers) and remove it (`slices.Delete`).
3. `delete(b.byID, id)`, set `Status = OrderCancelled`, return `nil`.

**Go to use:** maps, `delete`, comma-ok, `slices.Delete`.

**System idea:** the map gives instant lookup by id, but removing from the slice is still O(n).
Each data structure is fast for one thing. M10 revisits this.

**Tests:** cancel a resting order; unknown id; cancel twice (2nd → not found); cancel after it was
filled (→ not found); a cancelled order no longer matches.

**Watch out:** the map and the slices must always agree. Every place that adds or removes from
one must update the other. A test that checks `len(byID) == len(buys)+len(sells)` catches mistakes.

## F14 · Fuzz test `[ ]`

**File:** `orderbook/fuzz_test.go`
**What:** `func FuzzSubmit(f *testing.F)`: Go generates random inputs (type, price, qty) and you submit
them. After every submit, check the **invariants**, things that must always be true:
1. The book is never crossed: if both sides have orders, `BestBid < BestAsk`.
2. Nothing is lost: for each submit, sum of trade quantities `== OrigQty - Qty` of the incoming order.
3. Every side stays sorted best-first.

**Run:** `go test -fuzz=FuzzSubmit -fuzztime=30s ./orderbook`

**System idea:** example tests check cases you thought of; fuzzing finds the ones you didn't.
Invariant thinking is how databases and exchanges are tested in real life.
